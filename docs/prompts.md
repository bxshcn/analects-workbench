## 1. 角色与任务

你是一位精通现代前端架构（Vite、React、TypeScript）与数据可视化（D3.js）的全栈工程师。请构建一个名为《论语》知识图谱的 Web 应用：

- 首屏：人物关系有向弦图。
- 第二屏：完整的《论语》概念索引与章句考据系统。
- 纯客户端 SPA，数据异步加载，状态集中管理，URL 可深链。

## 2. 技术与架构规范

- 构建工具与框架：Vite + React 18+ + TypeScript，纯客户端 SPA。
- 状态管理：Zustand，单一 `useAnalectsStore`。集中管理：
  - Tab1 三关系单选与对数弧长开关；
  - 主图聚焦态；
  - 历史节点栈与游标；
  - 当前锚点节点；
  - 激活原文的关系对状态；
  - 数据包缓存、加载态、错误态与重试状态。
- 可视化：D3.js v7 的 `d3-chord`（ribbon）、`d3-shape`（arc），驱动几何计算；React 声明式接管 SVG DOM 渲染。
- 禁止使用 ECharts 等封装过死的高层图表库；禁止使用 Next.js。
- 样式：Tailwind CSS + Lucide React。宣纸暖白 `#FAF8F5` 学术排版；响应式 `70% : 30%` 网格分栏；隐藏滚动条；统一 `1.5px` 极细线性图标。
- 数据与代码分离：`src/data` 是只读源；`scripts/build-data.mjs` 生成 `public/data`；App 只 `fetch`，不 import 原始 JSON。
- 全站 UI 文案与示例不使用箭头字符。

## 3. 数据契约

### 3.1 只读源文件

数据原始文件位于 `src/data`，不得在运行时直接 import。

| 文件  | 内容 |
|--- |---|
| `nodes.json`  | 节点基础信息、原文引用、训诂、注疏、别名 |
| `edges.json`  | 强语义边 + 文本共现边 |
| `verses.json` | 全量《论语》章句与四类注疏 |

数据规模与分布不在本文档中硬编码；构建后统一写入 `scripts/output/data-snapshot.json` 与 `scripts/output/data-snapshot.md`，数据校验不比较任何固定总数。

源数据规则：

- `nodes.json` 不包含 `weight`、`degree`。
- `edges.json` 不包含 `weight`、`relation_zh`。
- `verses.json` 是章句唯一权威源。
- `share_refs`、`source_refs` 中的字符串都是 `verses.json` 的 `code` 外键。

### 3.2 节点

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识 |
| `type` | string | 8 类节点类型之一 |
| `canonical_name` | string | 规范名称 |
| `source_refs` | string[] | 该节点出现的章句 `code` 列表 |
| `gloss` | string | 训诂/概要释义 |
| `commentary` | string | 注疏/扩展释义 |
| `alias` | string[]? | 可选别名数组 |

节点类型：

| type | 中文标签 | 类型归类 |
|---|---|---|
| `person` | 人物 | 可视类型 |
| `virtue` | 德性 | 可视类型 |
| `vice` | 恶性 | 可视类型 |
| `persona` | 人格 | 可视类型 |
| `institution` | 制度 | 非可视类型 |
| `office` | 官职 | 非可视类型 |
| `polity` | 邦国 | 非可视类型 |
| `role` | 角色 | 非可视类型 |

“可视类型 / 非可视类型”是节点类型分类；“核心节点 / 扩展节点”是按是否参与强语义边计算的运行状态，二者不是同一维度，详见 3.5。

### 3.3 边

| 字段 | 类型 | 说明 |
|---|---|---|
| `source_id` | string | 源节点 `id` |
| `target_id` | string | 目标节点 `id` |
| `relation` | string | 8 类关系之一 |
| `directed` | boolean | 有向为 `true`；对称关系为 `false` |
| `share_refs` | string[] | 该边关联的章句 `code` 列表 |
| `source` | string? | 可选出处说明 |

关系枚举与中文名：

| relation | directed | relation_zh | 出向（主动） | 入向（被动） | 主要视图 |
|---|---|---|---|---|---|
| `PRAISES` | true | 赞美 | 赞美 | 受赞 | Tab1、底部 |
| `CRITICIZES` | true | 批评 | 批评 | 受批 | Tab1、底部 |
| `TEACHES` | true | 品评 | 品评 | 受评 | Tab1、底部 |
| `ADVOCATES` | true | 倡导 | 倡导 | 见倡 | 底部 |
| `WARNS_AGAINST` | true | 警戒 | 警戒 | 见戒 | 底部 |
| `CONTAINS` | true | 包含 | 包含 | 隶属 | 底部 |
| `CONTRASTS_WITH` | false | 对立 | 对立 | 对立 | 底部 |
| `CO_OCCURS_WITH` | false | 共现 | 共现 | 共现 | 底部 |

- UI 只允许使用本表的中文名，不得出现其他关系称谓。

### 3.4 章句

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 章句唯一标识 |
| `code` | string | 章句号，如 `12.1` |
| `chapter_num` | number | 篇序号 1 到 20 |
| `chapter_title` | string | 篇名 |
| `verse` | string | 原文 |
| `gloss` | string | 译文/训诂 |
| `annotation` | string | 注释 |
| `commentary` | string | 疏解 |
| `critique` | string | 评析 |

四类注疏字段由源数据提供；空字段在 UI 中自动隐藏，完整性统计见 `scripts/output/data-snapshot.md`。


### 3.5 派生字段

| 字段 | 生成位置 | 用途 |
|---|---|---|
| `edge.weight` | 拆分阶段 | 弦图 ribbon 值、胶囊权重、排序 |
| `relation_zh` | 拆分阶段 | 前端关系中文名 |

派生规则：

- `edge.weight = share_refs.length`；`share_refs` 不得为空；所有边均须关联至少一条章句。
- Tab1 弧长是在运行时对当前勾选关系的关联边 `edge.weight` 求和。
- 核心节点判定：参与至少一条强语义边；扩展节点判定：只参与共现边。该判定由前端从边集合现算，不依赖节点权重。
- 可视类型节点全部进入 `core-graph.json`；其中未参与强语义边者属于“可视扩展节点”，仍可在核心包中找到，但不属于“核心节点”。

## 4. 数据构建与加载

### 4.1 构建脚本

- `scripts/build-data.mjs`：
  - 读取 `src/data` 的三个只读文件；
  - 校验字段、外键、孤儿节点、重复边、关系枚举；
  - 派生 `edge.weight` 与 `relation_zh`；
  - 生成 `public/data` 数据包；
  - 生成 `scripts/output/data-report.json`、`scripts/output/data-snapshot.json` 与 `scripts/output/data-snapshot.md`；
- `scripts/validate-data.mjs`：
  - 采用关系规则，不比较任何固定总数；
  - 校验源数据结构、外键、非空 `source_refs` 与 `share_refs`、孤儿节点、重复边、自环边、强边端点类型；
  - 校验核心包、共现包、详情包、章句包与源数据的集合关系；
  - 校验 `meta.counts`、`meta.relationCounts` 由当前数据派生；
  - 校验 `meta.source` 的 SHA-256 与当前源文件一致；
  - 校验 `node.degree`、`node.weight` 未进入公开数据包；
  - 运行 `node scripts/validate-data.mjs --rules` 可查看 R01 到 R24 的规则说明。
- App 只 fetch `public/data`，禁止 import `src/data`。

### 4.2 数据包

| 文件 | 内容 |
|---|---|
| `core-graph.json` | 当前全部可视类型节点 + 当前全部强语义边（含 `weight`、`relation_zh`） |
| `node-details.json` | 当前全部节点的基础元数据 + `gloss` + `commentary` |
| `co-edges.json` | 当前全部共现边（含 `weight`、`relation_zh`） |
| `verses.json` | 当前全部章句全文与四类注疏 |
| `meta.json` | 由当前数据派生的版本、计数、关系分布、源文件 SHA-256 |

各包体积、gzip 体积、节点/边/章句计数与关系分布统一由构建脚本写入 `scripts/output/data-snapshot.md` 与 `scripts/output/data-snapshot.json`；校验脚本不比较固定数字。

数据包结构：

```text
core-graph.json    { nodes: CoreNode[], edges: CoreEdge[] }
node-details.json  { [id: string]: DetailNode }
co-edges.json      { edges: CoEdge[] }
verses.json        Verse[]
meta.json          { version, generatedAt, source, counts, relationCounts, weightRule, note }
```

### 4.3 加载时序与错误态

1. 首屏阶段：只请求 `core-graph.json`；渲染骨架屏，直到节点与强边就绪。
2. 后台阶段：首屏渲染完成后并行请求 `node-details.json`、`co-edges.json`、`verses.json`。
3. 详情包未就绪时：
   - 首屏图表可正常交互；
   - 底部扩展节点与共现组显示“数据加载中”；
   - “查原文”按钮禁用并显示加载态。
4. 请求失败：显示轻量错误条与“重试”按钮，不清空已加载数据。
5. 深链恢复：
   - 先解析 URL；
   - 若 `node` 在核心包中，立即恢复；
   - 若 `node` 只存在于详情包，先显示加载态，详情包到达后恢复；
   - 非法参数回落到默认态，不抛出错误。
6. 所有数据请求结果进入 Zustand，避免重复请求与多余重渲染。

## 5. 页面空间结构

页面采用自然垂直文档流，不使用底部悬浮遮挡层。

1. 首屏全景画布区：高度 `100vh`，包含顶部标题栏与主可视化画布。移动端使用 `100dvh`。
2. 底部详细面板区：位于首屏 `100vh` 之外的文档流中，宽度 `100%`，高度随内容自然撑开。
3. 双键快速电梯：
   - 监听全局键盘事件；
   - 排除输入框、文本域、可编辑元素聚焦；
   - 排除 `Ctrl`、`Meta`、`Alt` 组合键；
   - `j` 键：平滑滚动到第二屏顶部；
   - `k` 键：平滑滚动到页面顶部。

## 6. Tab1：人物关系网络

### 6.1 关系与节点

- 可视化形式：有向弦图，占据首屏主画布 100% 空间。
- 只呈现 3 类关系：
  - `PRAISES`：赞美；
  - `CRITICIZES`：批评；
  - `TEACHES`：品评。
- 节点：当前选中关系涉及的所有 `person` 节点。
- 默认选择“赞美”。
- 三项分别单选时，参与人物、边数、权重合计与占比由当前数据计算，具体数值见 `scripts/output/data-snapshot.md`。
- 节点弧长在对数弧长关闭时表示该人物在当前选中关系中的总关联权重；默认开启时表示 `Math.log1p` 缩放后的弧长值。

### 6.2 筛选器

- 位置：画布左下角，悬浮于画布上层。
- 样式：高对比度卡片，轻微毛玻璃 `backdrop-filter: blur(8px)`。
- 三个互斥单选项：赞美、批评、品评。
- 不设分割线、不设分组；不为三类关系预设颜色。
- 默认选择赞美。
- 筛选器内放置“对数弧长”开关，默认打开。
- 筛选变化时，节点集合、弦图布局与底部状态同步更新。

### 6.3 对数弧长

对数弧长只作用于 Tab1 弦图的几何，不改变任何权重数据、排序、章句数量或底部胶囊显示。

定义：

- 对每个人物 `p`，`rawTotal(p)` 为当前勾选关系中所有关联边的 `edge.weight` 之和。
- 弧长值 `arcValue(p)`：
  - 开关打开：`Math.log1p(rawTotal(p))`；
  - 开关关闭：`rawTotal(p)`。
- 所有人物按 `arcValue` 占比分配圆周弧段：
  - `angle(p) = arcValue(p) / 所有 arcValue 之和 * (2π - n * padAngle)`。
- 节点在圆周上的顺序：按 `arcValue` 降序；相同时按 `canonical_name` 升序。
- `padAngle` 默认 `0.01` 弧度。
- 在每个人的弧段内部，按关联边分配子弧：
  - 源端宽度：`weight(edge) / rawTotal(source) * arcValue(source)`；
  - 目标端宽度：`weight(edge) / rawTotal(target) * arcValue(target)`。
- 这样每个人的弧段总长严格等于 `arcValue(p)`；同一条边在两端可能有不同宽度，形成自然的收束效果。
- 开关关闭时，`arcValue` 等于 `rawTotal`，两端宽度一致，退化为普通弦图。
- 默认打开。切换时使用平滑过渡，不重建数据。
- 对数缩放使用自然对数 `log1p`，避免权重为 1 时取值为 0。

预期效果不硬编码具体数值；构建后由 `scripts/output/data-snapshot.md` 输出各筛选模式下的孔子弧长占比，验收时以该报告为准。

- 筛选器内显示小字提示：“弧长为对数缩放，权重数值以底部索引为准。”
- Tooltip 同时显示 `rawTotal` 与当前 `arcValue`，避免误解。

### 6.4 有向弦图几何

- 圆周外圈预留足够边距，完整显示人物标签，避免裁切。
- 源端弧段贴外圈；目标端弧段向内缩进约 6px，用几何表达方向性。
- 不使用任何箭头图标或箭头字符。
- 三种关系使用三种可区分颜色；同一人物内部的子弧按关系分组排列。
- 子弧排序：先出向，后入向；同方向内按关系顺序赞美、批评、品评；同关系内按 `edge.weight` 降序。
- 弦图丝带使用半透明填充；默认边透明度遵循第 7 节状态机。
- 所有连线设置透明宽热区，命中宽度不小于 8px。
- 节点标签显示 `canonical_name`；有别名的人物可在 tooltip 中显示别名。

### 6.5 交互

- Hover 节点：临时高亮该节点的一阶邻域。
- Hover 边：临时高亮该边及两端节点。
- Click 节点：锁定聚焦态，底部锚定该人物。
- Click 边：锁定边聚焦态，底部锚定源节点，并激活目标节点的“查原文”状态。
- Click 空白：恢复初始默认态。
- 键盘：节点与边可通过 Tab 聚焦，Enter 触发点击；Esc 清除锁定。
- 对数弧长开关切换不触发底部刷新，只重绘弦图几何。

## 7. 视觉降噪与高亮状态机

### 7.1 五档透明度

| 档位 | 透明度 | 使用场景 |
|---|---:|---|
| 焦点 | 100% | 选中节点、选中边、两端节点 |
| 直接关联 | 85% | 节点聚焦时的一阶边 |
| 次级上下文 | 30% | 边聚焦时两端节点的其他边与邻居 |
| 默认降噪 | 18% | 初始全局态的所有边 |
| 背景隐退 | 3% | 无关节点与边 |

### 7.2 状态

1. 初始默认态：
   - 所有节点 100%；
   - 所有边 18%；
   - 保留颜色混合，呈现宏观色彩分布。
2. 节点聚焦态：
   - 弦图：选中节点与直连邻居 100%，直连边 85%，其余 3%。
3. 边聚焦态：
   - 选中边 100% 并加高亮描边；
   - 两端节点 100%；
   - 两端节点的其他边与邻居 30%；
   - 其余 3%。
4. Hover 悬停：
   - 鼠标移入临时预览高亮；
   - 移出恢复锁定态或默认态。
5. Click 锁定：
   - 点击后才正式锁定并刷新底部详情；
   - 再次点击同一元素不重复写入历史。
6. Click 空白：恢复初始默认态。
7. 筛选变更：
   - 取消勾选即移除对应关系边与因此失去关联的节点；
   - 不做“保留但淡化”的处理；
   - 对数弧长开关只影响 Tab1 几何，不影响透明度状态机。
8. 所有连线设置透明宽热区，命中宽度不小于 8px。
9. 过渡使用 `transition` 或 `requestAnimationFrame`，避免布局抖动。

## 8. 底部完整索引框架

底部面板覆盖 8 类关系：7 类强语义关系与 1 类文本共现关系。不包含任何已删除的历史人物关系。

### 8.1 顶部吸顶历史栏

- 定位：`position: sticky; top: 0`，固定在底部面板最上方。
- 仅记录节点信息，不记录边。
- 视觉编码：
  - 节点语义色用于前置微图标；
  - 核心节点：`1px` 实线边框 + 纯白实底；
  - 扩展节点：`1px` 虚线边框 + 浅灰底。
- 历史容器单行横向排版，隐藏原生滚动条（`scrollbar-width: none`）。
- 鼠标垂直滚轮映射为平滑横向滚动。
- 溢出边缘添加渐隐遮罩，暗示可滑动。
- 新增节点或回溯点击时，`scrollIntoView({ inline: "center" })` 居中当前节点。
- 历史栈最大 50 条；超出时丢弃最旧记录。
- 点击历史中的旧节点：
  - 该节点成为当前锚点；
  - 截断其后的所有历史记录；
  - 同步刷新首屏与底部内容。
- 最右侧固定放置“清空历史”按钮，不随列表滚动：
  - 点击后仅保留当前节点作为新起点；
  - 按钮使用 Lucide 图标，带无障碍标签。
- 历史为空时显示轻量占位，不显示清空按钮。

### 8.2 2:1 非对称双栏主体

- 左侧内容栏：占 2/3 宽度，分上下两区。
  - 上部：当前节点档案。
  - 下部：关系章句考据区。
- 右侧关系索引栏：占 1/3 宽度。

当前节点档案：

- 名称：`canonical_name`。
- 类别标签：人物、德性、恶性、人格、制度、官职、邦国、角色。
- 别名：`alias` 存在时显示，多个别名用顿号分隔。
- 概要释义：显示 `gloss`。
- 扩展释义：显示 `commentary`，默认折叠，点击展开。
- 若详情包尚未加载，显示骨架占位。

关系章句考据区初始态：

- 居中展示一条极简提示：“点击右侧关系索引栏中的查原文图标，在此调阅双方相关的《论语》章句。”
- 提示文案不使用箭头字符。

### 8.3 五级宏观分组

严格按以下顺序排列，空组自动隐藏：

1. 主动输出：当前节点作为动作主语。
2. 被动承受：当前节点作为动作宾语。
3. 对立张力：对称关系。
4. 文本共现：弱语义关联。
5. 典籍出处：当前节点出现的章句列表。

分组映射：

| 分组 | 关系 | 方向 | 中文 |
|---|---|---|---|
| 主动输出 | `PRAISES` | 出向 | 赞美 |
| 主动输出 | `CRITICIZES` | 出向 | 批评 |
| 主动输出 | `TEACHES` | 出向 | 品评 |
| 主动输出 | `ADVOCATES` | 出向 | 倡导 |
| 主动输出 | `WARNS_AGAINST` | 出向 | 警戒 |
| 主动输出 | `CONTAINS` | 出向 | 包含 |
| 被动承受 | `PRAISES` | 入向 | 受赞 |
| 被动承受 | `CRITICIZES` | 入向 | 受批 |
| 被动承受 | `TEACHES` | 入向 | 受评 |
| 被动承受 | `ADVOCATES` | 入向 | 见倡 |
| 被动承受 | `WARNS_AGAINST` | 入向 | 见戒 |
| 被动承受 | `CONTAINS` | 入向 | 隶属 |
| 对立张力 | `CONTRASTS_WITH` | 双向 | 对立 |
| 文本共现 | `CO_OCCURS_WITH` | 双向 | 共现 |
| 典籍出处 | `source_refs` | 无方向 | 出处 |

- 不再使用任何其他关系称谓。
- 被动组的关系中文名由 UI 派生，不写入数据。

### 8.4 胶囊形态

形态 A：有原文的概念关联，分段式双热区胶囊。

- 结构：`[ 节点名称 · 权重 | 查原文图标 ]`，中间以细线分隔。
- 权重使用派生后的 `edge.weight`。
- 点击左侧节点名称：
  - 将该关联节点设为新锚点；
  - 写入历史栏；
  - 联动首屏画布。
- 点击右侧查原文图标：
  - 保持当前锚点不变；
  - 高亮该图标；
  - 在左侧下部渲染双方相关的全部章句。
- 若该边有多个章句，全部以垂直卡片堆叠展示；每个卡片默认显示 `[篇名·章句号]` 与原文，注疏字段默认折叠。
- 若只有一个章句，同样默认显示原文与折叠注疏，不做特殊展开。
- 若目标节点是扩展节点，胶囊保留前置语义色点与虚线边框。

形态 B：无原文的防御性兜底。

- 校验要求 `share_refs` 非空，因此形态 B 不会由当前数据产生；保留为 UI 防御态。
- 若未来出现无 `share_refs` 的边：
  - 省略查原文图标与权重；
  - 渲染为纯概念跳转胶囊 `[ 节点名称 ]`；
  - 点击直接跳转节点，不触发原文查询。

形态 C：第五组典籍出处，单热区阅读胶囊。

- 结构与上方胶囊一致的高度、圆角、流式排版。
- 渲染为 `[ 篇名·章句号 ]`，如 `[ 颜渊·12.1 ]`。
- 点击整颗胶囊：
  - 不改变当前锚点；
  - 不写入历史栏；
  - 仅高亮该胶囊；
  - 在左侧下部渲染该章句完整原文；
  - 自动高亮当前节点关键词。

### 8.5 章句卡片

- 默认态：显示 `[篇名·章句号]` 与《论语》原文正文。
- 原文中的当前关系双方关键词进行高亮标注。
- 每张卡片右上角提供“展开注疏”与“收起注疏”切换。
- 注疏字段顺序：
  1. `gloss`；
  2. `annotation`；
  3. `commentary`；
  4. `critique`。
- 空字段自动隐藏；章句注疏字段完整性统计见 `scripts/output/data-snapshot.md`。
- 卡片展开动画使用高度过渡，避免布局跳动。
- 顶部语境头栏：
  - 显示当前关系三元组，不使用箭头字符；
  - 主动示例：`孔子 · 品评 · 仲由`；
  - 被动示例：`仲由 · 受评于 · 孔子`；
  - 右侧显示匹配章句总数；
  - 提供“折叠全部注疏”按钮。
- “折叠全部注疏”按钮仅当列表中至少一张卡片处于注疏展开状态时高亮可用；点击后全部收起。
- 头栏与卡片之间保持固定间距，滚动时头栏可吸顶但不能遮挡正文。

### 8.6 排序、截断与高亮

组内排序（前四组适用）：

1. 先按具体关系类型归类；关系顺序为赞美、批评、品评、倡导、警戒、包含、对立、共现。
2. 再按目标节点的语义类型聚类：
   - 人物；
   - 德性；
   - 恶性；
   - 人格；
   - 制度；
   - 官职；
   - 邦国；
   - 角色。
3. 同类型内按 `edge.weight` 降序。
4. 权重相同时按目标节点 `canonical_name` 升序。

第五组“典籍出处”不适用上述关系/类型排序，按 `chapter_num` 升序，再按 `code` 升序。

截断与展开：

- 文本共现组超过 15 项时，默认展示前 15 项，并提供“展开全部”。
- 典籍出处组超过 15 项时，默认展示前 15 项，并提供“展开全部”。
- “展开全部”后每批渲染 50 项，提供“收起”恢复前 15 项。
- 高频节点的共现与出处必须使用分批渲染，避免一次性挂载数百个 DOM 节点。

高亮规则：

- 高亮词 = `canonical_name` + 长度不小于 2 的 `alias`。
- 采用最长匹配优先，避免短词覆盖长词。
- 单字别名仅在没有任何本名或多字别名命中时启用。
- 本名不在原文且无别名的概念/人格节点不做强行高亮，保留干净原文；具体名单见 `scripts/output/data-snapshot.md`。
- 只高亮当前关系双方的关键词，不对全文做泛化关键词高亮。
- 高亮使用轻量背景色或下划线，不改变原文排版。

权重与计数：

- 胶囊权重 = `edge.weight`。
- 语境头栏“匹配章句总数” = `share_refs.length`。
- 典籍出处数量 = `source_refs.length`。
- 对数弧长不参与底部任何排序或计数。

## 9. 首屏与底部面板的跨屏联动

1. 在首屏点击节点：
   - 保持视口在首屏；
   - 底部边缘弹出轻量提示：“已锚定 [节点名] · 按 j 查看索引详情”；
   - 静默将底部面板锚定至该节点；
   - 写入历史栏。
2. 在首屏点击关系边：
   - 默认将底部锚定为该关系的源节点；
   - 写入历史栏；
   - 自动激活目标节点的查原文状态；
   - 左侧下部直接就绪展示双方关联章句。
3. 有向关系：
   - `source_id` 为锚点；
   - `target_id` 为查原文目标。
4. 无向关系：
   - `CONTRASTS_WITH` 使用数据中的 `source_id` 作为锚点；
   - 两端视觉等价，不额外制造方向语义。
5. 在底部面板探索扩展节点：
   - 扩展节点指只参与 `CO_OCCURS_WITH` 的节点，包含人物、德性、恶性以及制度、官职、邦国、角色；
   - 保持当前视口留在底部详细面板；
   - 不物理锁定首屏交互；
   - 首屏主图恢复全局默认态，边透明度 18%；
   - 首屏顶部展示轻量状态条：“当前正在索引区探索扩展概念：[名称]（未参与强语义关系） · [返回上一个核心节点]”；
   - “[返回上一个核心节点]”是按钮，点击后回到历史栈中最近的核心节点。
6. 提示与状态条不得长期遮挡画布内容；3 秒后淡出或提供关闭按钮。

## 10. URL、SEO 与社交媒体

### 10.1 URL 状态同步

查询参数：

| 参数 | 取值 | 说明 |
|---|---|---|
| `node` | 节点 `id` | 当前锚点 |
| `target` | 节点 `id` | 当前查原文目标 |
| `rel` | 8 类关系之一 | 当前激活关系 |
| `dir` | `in` 或 `out` | 当前激活方向 |

规则：

- 首次加载优先解析 URL 并恢复状态。
- 缺失参数使用默认态。
- 非法参数回落到默认态，不抛出错误。
- 交互切换时使用 `window.history.replaceState` 静默更新地址栏。
- 监听 `popstate`，按当前 URL 重新解析并恢复状态；无法解析时回落到默认态。
- 禁止把历史列表写入 URL。
- 仅对“已提交”的点击状态同步，不对 Hover 同步。
- 对称关系可省略 `dir`；有向关系必须携带 `dir`。
- 本文档只保证锚点、目标、关系、方向可深链；筛选状态与对数弧长开关不写入 URL，刷新后回落默认值。
- 切换节点时更新 `document.title`，格式为 `节点名 · 《论语》知识图谱`。

### 10.2 静态 SEO

在 Vite 的 `index.html` 中配置：

- `<title>《论语》知识图谱</title>`
- `<meta name="description" content="交互式《论语》知识图谱与古典文献索引工作台，支持人物品评网络、按关系分组的索引、全量原典章句与历代注疏考据。">`
- `<meta name="keywords" content="论语,知识图谱,孔子,儒家思想,古典文献索引,数字人文">`
- 不需要在客户端动态修改 `<meta name="description">`。
- `<div id="root">` 外添加简洁的 `<noscript>` 核心内容摘要，说明站点主题与主要视图；不要写死节点、边、章句数量，统计以 `scripts/output/data-snapshot.md` 为准。
- `lang="zh-CN"`。

### 10.3 Open Graph 与 Twitter Card

在 `index.html` 中配置：

- `og:type` 为 `website`；
- `og:title`；
- `og:description`；

`public/og-preview.jpg` 必须存在，尺寸 1200×630，使用宣纸白、墨灰、朱砂红、石青蓝的图文卡片。当前仓库已提供同尺寸占位图 `public/og-preview.jpg`；正式发布前需确认或替换为正式图，并在验收清单中标注占位状态。

- 校验要求 `share_refs` 非空；所有边均须关联至少一条章句，形态 B 仅为 UI 防御态。

### 14.4 验证命令

```bash
node scripts/build-data.mjs
node scripts/validate-data.mjs
node scripts/validate-data.mjs --rules
```

校验脚本按关系规则运行，不比较固定总数；当前快照由构建脚本写入 `scripts/output/data-snapshot.md` 与 `scripts/output/data-snapshot.json`。

验收时同时检查：

- `public/data` 的五个文件存在；
- `core-graph.json` 的 gzip 体积小于 30KB；
- 首屏不请求 `node-details.json`、`co-edges.json`、`verses.json`；
- `public/og-preview.jpg` 存在且为 1200×630；当前为占位图，正式发布前需确认或替换；
- 需要核对数据统计时查看 `scripts/output/data-snapshot.md`。
